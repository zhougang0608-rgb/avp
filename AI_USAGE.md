# AI Assistance Record

## 21 October 2026 - Version 1

The owner asked OpenAI Codex to organise a new repository into stages, based on an existing speech-recognition project.

Codex reused the existing name list and recording script, simplified the shared settings, implemented basic dataset checks, prepared documentation and ignore rules, and checked the resulting files. The original recording code had also received AI assistance, as recorded in the existing project's AI usage record.

Existing audio was used for read-only checks. No new microphone recordings, MFCC extraction, neural-network training or recognition evaluation were performed for this version. This is a new staged baseline, not a reconstruction of earlier development history.

The owner is responsible for checking recordings and labels, understanding the code, and explaining the work independently during the assessment.

## 22 October 2026 - Version 2

The owner asked Codex to prepare the next stage. Codex adapted the existing project's baseline MFCC implementation into this repository, added the frame/FFT settings and a feature-checking command, and updated the documentation. Optional delta/energy experiments and neural-network code have not been included at this stage.

Codex ran feature checks on 400 existing development recordings, compared one feature array to the existing implementation, and checked frame boundaries, filterbank properties and invalid inputs. These were software/feature checks, not recognition-accuracy tests. No new microphone recording or model training was performed.

The owner should learn and explain each MFCC stage. The current commits document actual staging work on these dates, not a claim that the reused code was first developed on those dates.

## 23 October 2026 - Version 3

The owner asked Codex to prepare the third stage. Codex adapted the original complete project's baseline convolutional architecture and training/validation approach, added development-data loading and training-only normalisation, and wrote the training command and documentation.

Codex ran one actual 26-band baseline training experiment on the existing 400 development recordings with a fixed 320/80 split. It checked stratification, disjointness, repeatability and independence of the normalisation statistics from validation values. The saved model/statistics were reloaded and the validation predictions matched; the run achieved 67/80 (83.75%) validation accuracy. No test recordings were read by this training run, no configuration sweep was performed and no new microphone recording was made.

This new run reuses existing development recordings and baseline design. It does not establish that the overall project was developed from scratch on these dates or that previously inspected test data is untouched. The owner must understand and explain the model, split, normalisation, learning curves and limitations.

## 24 October 2026 - Version 4

The owner asked Codex to prepare the fourth stage and limit the overall plan to five versions. Codex adapted optional delta and energy features and parameterised the convolutional model based on the existing complete project. It added a seven-configuration comparison command, separated the baseline and selected-model configuration files, and updated documentation.

Codex ran all seven experiments on the existing development recordings, using the same fixed 320/80 split and training-only normalisation. Actual validation results selected the 40-Mel-band model at 72/80 (90%); the energy configuration tied, so the first-in-order rule retained the former. The selected model/statistics were saved, reloaded and checked. Feature parity/dimensions, single-factor changes and split/statistics behaviour were checked. No test recordings were read for this comparison, and no microphone or noise-condition experiment was performed.

Results were generated by this run rather than imported from earlier result files. The staged repository still reuses existing code and recordings; its dates describe current work and do not recreate earlier development history. The owner must learn and explain the comparison, selection rule and limitations.
